## Correctness spot-checks (own analysis, not just evidence trust)

- **Concurrent `invoke()` calls cannot both pass the active-prompt check.** `lifecycle.active` is set synchronously in `invoke()` before its first `await`; since calling an async function runs synchronously up to its first await, a second `invoke()` call issued via e.g. `Promise.all([...])` only begins executing after the first call's synchronous prefix (which sets `lifecycle.active`) has already run. I traced this explicitly since it's easy to get wrong with async functions; it is correct here.
- **Abort-vs-callback race in `invokeHermesCli`'s beforeSpawnSession gate:** implemented as a hand-rolled race between an abort-triggered reject and the callback's own promise, with a cancellation-recheck (`if (signal?.aborted) throw`) immediately after the race settles. This correctly handles the case where the callback "wins" the race (resolves) at nearly the same tick the signal aborts - the recheck catches it since JS execution between the two events is not truly concurrent.
- **`onAbort`'s escalation timer and the `finally` block's `waitExit()`+`clearTimeout(escalation)` don't double-kill or leak.** If the child exits from SIGTERM alone before the 2s mark, `waitExit()` resolves, then `clearTimeout(escalation)` runs before the escalation callback could fire - deterministic ordering, no race, since Node's timer/event-loop semantics are single-threaded.
- **`session.dispose` / `runtime.dispose` idempotency:** a second call sees `lifecycle.active === undefined` (already cleared by `invoke()`'s own `finally`), so `active?.controller.abort()` / `active?.completion.catch(...)` are no-ops - safe to call repeatedly, matching the "repeated disposal is safe" requirement.
- **Mock/fixture updates are load-bearing, not incidental.** `cli-spawn.test.ts`'s `emitError` now also emits `close` (real Node child processes always follow an `error` event with a `close` event; the fake previously didn't), and two existing tests now explicitly `emitClose(...)` after their timeout/abort trigger - both changes are *required* for the new `await supervised.waitExit()` in the `finally` block to resolve in these tests, not cosmetic. I confirmed this is a correct fixture fix reflecting real Node behavior, not a behavior change smuggled into the tests.
