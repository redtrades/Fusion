Start the native codex app-server --stdio child rather than PTY for this protected Codex path; retain current workflow runCliAgentNode, native session allocation, ownership/fences, budgets, cancellation and task outcome path. This is an explicit transport change, not an interface that pretends JSON-RPC is terminal keystrokes. Existing interactive adapters remain on their current path. Dashboard terminal attachment for this transport must be read-only event rendering; do not pipe user bytes into RPC. No broader transport/plugin framework.

## Fresh path, inode and first-request accounting
1. Native record allocation remains before child launch. After handshake verify task/project/current lease, process alive, requested model/provider/cwd and budget still admitted; atomically persist exact threadID + canonical native future path and fresh-only origin. Reject previously known native ID, resume mislabeled fresh, unexpected pre-existing usage, null path or inconsistent responses. No status-screen UUID substitute.
2. If path is absent, verify canonical existing parent and basename under configured native session storage; retain the exact native-returned path, never invent/open-create it. Typed awaiting-file state has NO inode and counters0; no empty-string/sentinel inode or fabricated baseline. A native-created zero-byte file is still awaiting valid header. A native-created complete metadata-only file can bind inode only after exact header/cwd validation and verifying no prior usage. Never treat arbitrary existing file as fresh0.
3. Before turn/start, existing bounded observer is armed on that exact path and fresh ID, with durable pending checkpoint and remaining budget check. First successful open verifies regular file, canonical identity, header first, payload.id==thread.id and canonical cwd==admitted cwd; then persist dev:ino exactly once. After binding, replacement/truncation/path redirection fails. This is polling ONE authoritative path through current observer, not discovery globbing or a new generic watcher.
4. First data read starts byte0 and is chargeable: use baseline:false semantics for observations; current read(true) would incorrectly suppress the first request. A fenced empty fresh-admission marker must initialize ledger separately so initial cumulative request counts in full. Repeated cumulative/replayed frames remain idempotent. Resumed sessions retain real prior ledger/cursor and cannot reset to fresh0.
5. Missing file/header/usage by final drain, malformed counters, bound-file changes, owner supersession or accounting ACK failure kills/blocks and denies success. Await final parser queue and store ACK before releasing native task/lease. Existing observed cap semantics allow in-flight overshoot; do not claim a predictive zero-overshoot cap. Native path absence while waiting is not a stream error until declared creation deadline, but cannot result in silent successful completion.

Preserved guard meaning: before the first model request the host now has native-issued exact ID AND authoritative future path, rather than waiting for a hook that itself needs a turn. File/inode existence is explicitly pending; if product policy requires existing inode before inference, this API still does not satisfy that stricter requirement and no patch should claim otherwise. This plan narrows the prior missing-path gap; it does not fabricate file evidence or weaken identity/ownership checks. Mixed PI/CLI and fleet limits remain unchanged.
