## Mutation/refusal contract

Protected task processing requires the already linked PR and normal per-task branch route. Missing PR, unsupported shared/workspace scope or absent head/admission proof refuses without creating another PR or using a direct AI merge fallback.

At entry and after every awaited refresh/settings/status stage leading to mutation, re-read the native row. Require not deleted/paused, the same selected workflow/merge column, and exact captured checkout run, epoch, agent and host. After the **last** awaited native ownership read, check signal and compare fields synchronously immediately before github.mergePr; no intervening awaited settings/read step. Existing caller cancellation remains wired through the queue's controller.

If refresh produces B while reviewed A was supplied, return/throw the typed `stale-head` refusal with zero merge call. When the head matches, always give the provider `expectedHeadOid:A`, even if githubNativeAutoMerge is true; do not pass auto:true for this protected attempt. Provider stale-head errors stay stale-head, not generic merge-failed/retry. Stale owner/Reset produces `merge-request-superseded`; unavailable admission is `merge-authority-unavailable`. These outcomes stop the protected graph attempt and require fresh authority; they must not schedule an unprotected retry or clear a replacement owner's state. Preserve existing unprotected semantics.

A provider's open response stays waiting. A provider's merged response, including exception reconciliation, must have the authoritative exact head A and still-current protected owner before finalization. Do not equate merged-requested with merged. The remote head conditional protects GitHub's own race; no claim that a local read atomically prevents a Reset occurring after a remote request is already sent.
